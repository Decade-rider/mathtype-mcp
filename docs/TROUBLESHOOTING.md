# 排错、升级与卸载

## 连接不上 / 工具数量不对

先在项目目录运行 `uv sync --locked` 和 `uv run --no-sync python scripts/smoke_mcp.py`。
0.2.0 应提供 12 个工具。客户端仍显示旧接口时重新加载 mathtype 服务；服务重启后重新获取文档/公式 ID。
路径移动后需要重新生成客户端配置。注册脚本不会覆盖同名冲突条目，请比较预览结果，仅修改 mathtype 条目，保留其他服务。

## Word 文档列表为空

只列出该服务可访问的 Word 实例，并不证明所有 Word 实例均无文档。可提供本地完整路径明确打开，或确认文档与服务运行在同一桌面用户会话中。不要通过猜测文档 ID 操作。

## 模板找不到

默认按已安装 Word 的位数查找 MathType Office Support 模板。自定义安装位置可在服务环境中设置 `MATHTYPE_MCP_TEMPLATE` 为正确模板完整路径。不要从网上下载未知宏模板，也不要为此关闭全部宏安全检查。

## Word“无法创建工作文件，请检查临时环境变量”

当前项目没有验证或自动修复这一问题。健康检查只覆盖部分静态信息。

记录发生错误的具体工具、参数、时间及客户端启动配置，检查**实际服务进程**的 TEMP、TMP、APPDATA、LOCALAPPDATA 与 Word 缓存目录；终端中的正常环境不一定等于客户端子进程环境。目录存在也不必然代表该进程有写权限。

不要仅凭这条提示删除注册表项、清空所有缓存或重置全局环境。不要盲目重试文档修改。先确认有无未保存文档和阻塞弹窗，必要时用新建的空白测试文档排查。

## 编号、样式与保存

连续编号支持 (1)、(2)…；章节/自定义格式配置和引用刷新暂未实现。已有公式需独占段落才能补编号。
手工删除或移动后调用 `word_refresh_equation_numbers`。锁定编号会提前报错。
两种 MCP 样式是项目排版标记，不是 MathType 原生编号机制本身；手动改样式名可能影响识别。

## 超时或弹窗

Office COM 调用可能被弹窗阻塞。客户端超时不是操作回滚，也不是底层调用已终止。检查文档后再行动，避免重复插入。项目不强行结束用户 Word 进程。

## 卸载

在客户端 MCP 配置中移除或禁用 **mathtype** 条目并重新加载客户端。不要删除其他服务条目或整份配置。确认服务已退出后，可移除项目目录；项目中的测试输出如需保留请先另行保存。
注册脚本产生的配置备份存放在客户端配置文件旁边，不应上传到公开仓库。无需卸载 Word 或 MathType。
